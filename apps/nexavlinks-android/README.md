# Nexa 签到助手（Android MVP）

独立 Android 工程，不依赖 Metapi 服务。Android 9+，最多 9 个账号；展示原站今日实际消费、签到状态，打开隔离的原站页面由用户手动完成验证码和签到。

## 安全与状态规则

- 每个槽位一个私有进程和 WebView 数据目录；主进程禁止创建 WebView。不是无痕窗口，也不是全局切换 Cookie。
- 添加/更新凭证时 GET `/api/v1/auth/me` 绑定不可变用户 ID。相同 ID 不重复添加，更新凭证不能换成其他 ID。
- 凭证使用 Android Keystore AES-GCM 加密，保存在 no-backup 目录。浏览器自己的 Cookie/localStorage 位于应用私有 WebView 目录，由 Android 沙箱保护，**不等同于 Keystore 加密**。应用禁止备份、截图，不提供导出或凭证日志。
- Native 请求使用固定站点白名单。Nexa 唯一 POST 为 `/api/v1/auth/refresh`，不发送其签到 POST；Router 一键签到另允许 AnyRouter 的 `/api/user/sign_in`，并先核实该站点用户身份。所有请求不跟随重定向，限制体积及连接/读取/总请求时间。
- 签到浏览器先在无站点脚本的同源空白页恢复并核验身份，再加载原站；页面加载完成后再次核验，匹配前不显示。重新进入前台也重新核验，不使用其他槽位凭证兜底。登录模式例外：先清理该槽位会话并显示原站登录页，检测到令牌后走 Native 身份校验；只接受同一次登录事务、槽位和账号修订匹配的结果。
- Nexa 不发送签到 POST、自动点击或绕过验证码；Router 按用户一键操作触发已限定的接口，不绕过验证。页面返回本身不算成功，必须有原站结果依据。
- 失败显示待核实/错误，不伪造零消费或未签到。首页保留带查询时间的历史快照（非实时）；刷新失败的字段清空，不借用旧值掩盖失败。上海日期跨天只使今日字段失效，不触发请求；账号修订或查询被替代时丢弃旧结果。
- 删除需用户确认，先清理该槽位浏览器状态再移除加密记录。清理未确认则保留账号。

## 0.6.0 Router 多站接入（实验版）

- 添加账号时选择 Nexa / AgentRouter / AnyRouter，总计仍最多 9 个独立进程槽位；旧记录自动归为 Nexa，无需迁移/重登旧 Nexa 账号。相同用户 ID 在不同站点不冲突，凭证、快照、会话指纹及去重键绑定站点。金额按站点分别汇总，不跨站混加。
- Router 首次登录优先沿用用户现有 **Linux DO**：内嵌浏览器仅在 Router 登录模式允许 `connect.linux.do`、`linux.do` 的 HTTPS 顶层跳转和站点 OAuth 弹窗；密码/授权交给网页，Native 不读取密码。GitHub 暂未开放，不需要为了本实现改绑。可能被登录方拒绝内嵌浏览器，此项尚未设备验证。
- Router 会话采用站点 Cookie，而非 Nexa refresh token；只读取该站点 API 路径的 Cookie，验证 `/api/user/self` 的 user ID、同一事务/页面及最新 Cookie 未变化后加密保存；Linux DO Cookie 仍在槽位浏览器私有目录，不复制给 Router Native 请求。重新登录/删除会清理本槽位浏览器，其他槽位不受影响。
- “刷新数据”更新 Nexa 和 Congee，不请求 Router；“一键签到”仅处理 AgentRouter/AnyRouter 且跳过本地已明确确认今日签到的账号。普通启动、通知、前后台切换不自动签到，操作被拒/超时不自动重试。Nexa 原有人工验证码流程不变。
- AgentRouter 的公开前端 `index-Cs_52wE9.js` 可见登录后 `checked_in` 奖励回执；[第三方签到实现](https://github.com/musnows/anyrouter-check-in/blob/main/utils/config.py) 将其 `/api/user/self` 作为触发点，将 AnyRouter 配为 `POST /api/user/sign_in`。AgentRouter 仅请求自身 `/api/user/self`；AnyRouter 先核实身份，再一次 POST，最后重新核实身份。不是实测过两站全部账号的协议保证。
- 严格判定：普通 GET 200/success 只表示用户信息成功，不表示已签到；`checked_in=true` 或明确 `checked_in_today` 才用于判断，AnyRouter 接受签到端点严格布尔 `success=true` 且无矛盾。无字段/矛盾/验证异常显示待核实；不按余额变化、响应文字“success”、模糊“已签到”子串推断。
- **AnyRouter 在此次无登录访问中返回 WAF 浏览器验证页**。本版本不破解验证码、不生成验证 Cookie、不伪装绕过 WAF；若 Native 请求仍被验证拦截，会提示回原站处理，不能保证一键成功。Linux DO OAuth、真实签到 POST/奖励确认、Cookie 时效均需真机验收。
- 额度取 `quota`/`used_quota`，使用网页登录保存的原站 `quota_per_unit` 换算为 USD（小数 8 位）；单位缺失显示未知，不硬编码换算。Router 无每日消费/订阅数据时不冒用 Nexa 字段。会话过期需重新登录，无确定到期时间则不伪造通知。
- 用户主动登录/查看原站时，站点自己的登录或 `/self` 接口可能同时发签到奖励；这不是应用后台自动签到。网页登录后使用已核实响应更新卡片，不再自动额外触发 Router 请求。

## 0.5.1 签到资格与订阅时间

- 订阅展示区明确区分**订阅到期时间**与每个周期的**额度预计重置时间**（上海时间），不是把数据查询时间当作重置时间。原站 `AppLayout.vue_vue_type_script_setup_true_lang-D0xtPYM_.js` 使用 `*_window_start` 加周期长度：小时采用 `hourly_reset_hours`（缺失/0 默认 1 小时），日 24 小时、周 168 小时、月 720 小时（滚动 30 天）。本地仅按该公开规则计算预计边界，不新增请求。
- 一天以内套餐的日额度随套餐到期结束；套餐先于下次周期边界到期时，显示“到期结束 / 不再重置”。未提供起点、字段异常、已暂停/撤销/过期等情况不编造下次重置时间。已过边界的缓存标为待刷新，金额灰显为“上次剩余”，不本地清零用量、不自动补满，也不自动滚动日期。
- 原站 `CheckInChallengeDialog-BXvSmu0a.js` 查询 `GET /check-in`，`CheckInView-Aicq9fuR.js` 用 `eligible === false` 提示 `CHECKIN_USAGE_REQUIRED`。现直接读取同一状态响应的布尔 `eligible`，未签到卡片显示“可签到 / 暂不可签到 / 资格待核实”，不额外查昨天、不增加请求数。
- 用户提到的昨日/今日消费门槛交给原站判定，不以今日消费 ≥ 0.4、历史快照或不完整昨日数据在本地猜测；这里没有取得昨日具体消费金额，也没有独立核实两日门槛的组合规则。字段缺失或非布尔一律未知，跨天/原站返回使旧资格失效；仍需用户手动完成原站验证码，资格不是签到成功。
- 兼容旧加密快照：旧版本未保存重置/资格字段时明确未知，刷新后读取。原有并发、通知、操作后单账号更新策略不变。

## 0.4.1 刷新提速与订阅卡片

- 全部刷新改为**最多 3 个账号并发**，移除账号之间固定 2 秒等待，任一账号完成就立即处理下一个。主进程统一控制 3 个执行名额，同账号仍严格去重/串行续期；不额外并发一个账号的请求，不增加单次查询接口数，不自动重试失败。实际耗时仍取决于原站与网络，未测得固定加速倍数。
- **新增/重新登录成功且加密保存完成后自动刷新该账号**；取消登录、保存失败不刷新。**签到页返回后只刷新刚操作的账号**（验证槽位与修订仍匹配），不依赖网页返回码判断成功，也不误刷其他账号。即使只打开页面没签到，返回后也查一次真实状态。
- 操作后更新优先排在等待队列前面，不中断正在执行的请求。进入首页、普通前后台切换、改备注、跨天仍不触发联网；通知仍只做本地提醒。操作后自动更新复用原有续期＋查询链路，每账号最多 1 POST + 4 GET。
- 订阅改为独立白色圆角套餐卡片：套餐状态标签、完整到期时间、大号剩余金额、各周期用量条、已用/上限分列。70%/90% 用量呈黄/红色，过期或不可用套餐灰显；未知用量不画虚假 0% 进度，超额进度封顶但显示真实已用，零额度不会当无限。

## 0.3.1 到期提醒

- **系统通知＋首页提醒**：根据已保存的 access token 到期时间，在到期前约 1 小时提醒；首页/账号卡片标黄，过期标红。首页在前台每分钟仅更新本地显示，不增加原站请求。
- 通知点击只打开首页，由用户手动刷新续期，不自动续期。refresh token 的到期时间未由原站提供，因此本功能不能预测刷新令牌失效；旧账号没有到期时间时显示未知，不伪造日期。
- Android 13+ 首次打开此版本请求通知权限；拒绝不影响其他功能，也不会反复弹出。首页“到期提醒设置”可启用/关闭系统提醒、跳转应用或通知渠道设置；通知被禁用时明确提示，首页提示继续保留。
- 所有账号合并为一个普通 `AlarmManager.setAndAllowWhileIdle` 本地定时检查，不申请精确闹钟权限，不运行前台常驻服务。不打开 App 时也会尝试提醒，但 Doze、省电/自启动限制和系统通知设置可能导致延迟或不送达；强行停止应用后须重新打开恢复，不能保证精确提前一小时。
- 成功登录、轮换凭证、修改账号或删除账号后，保存完成才在同一账号锁内重新排期；过时的闹钟触发时重新读取最新账号，续期后取消旧通知，删除后不再提醒。收到开机完成（解锁后）、应用升级、系统时间/时区变化时恢复/重排本地提醒，不联网。
- 同账号同一到期时间，“即将到期”和“已到期”各更新通知一次；重复广播/进入首页不重复发。已发过的提醒在关闭再开启后不会重复补发同阶段。若首次送达已过期，则直接显示已到期，不再发过时的预警。
- 系统通知只显示通用提醒文字，不含账号备注、ID、余额或令牌；锁屏仅显示通用提示。闹钟 Intent 不含凭证，偏好文件仅保存开关与散列去重标识；Token 仍仅在既有加密账号文件中保存。

## 0.3.0 手动刷新时续期

- 已核对亚洲站公开前端 `assets/index-DswOi53U.js`：`POST /api/v1/auth/refresh`，JSON `{refresh_token: ...}`；返回新的 `access_token`、`refresh_token`、`expires_in` 与 `token_type`。未使用用户截图中的令牌发送请求。
- 网页登录时一起采集同一份 `auth_token`、`refresh_token`、`token_expires_at`（原站用 `expires_in` 秒计算的毫秒时间戳）；再次核对三项未变化及用户身份后，全部写入原有 Keystore 加密账号文件。
- 点击单账号“刷新”或“刷新全部”，每个具备续期凭证的账号先续期一次，再查询身份/余额、消费与签到。无后台定时续期、无启动刷新、无分钟冷却。续期响应先原子加密保存，再执行身份 GET；任何身份不符均不展示该账号数据。不在续期失败后悄悄用旧令牌继续查询，不自动重试轮换请求。
- 新凭证由主进程存储对象持有；Activity 重建不取消已发出的轮换保存，账号修改采用修订校验；同一账号续期期间不允许重新登录、删除或打开签到页。修改备注保留两种令牌及到期时间。
- 令牌轮换由 Native 单独负责：登录交接时销毁 WebView，进入签到页前清理该槽位旧会话，仅注入最新 access token，不注入 refresh token/网页自动续期时间，避免网页与 Native 各自消费同一个刷新令牌。访问令牌已过期时先提示用户手动刷新再打开签到页；页面停留到过期则需返回刷新。
- **旧版没有保存 refresh token，因此覆盖安装后须在管理中为旧账号重新登录一次**。没有续期凭证时仍兼容旧查询路径，卡片明确提示不具备续期能力。
- `expires_in` 是 access token 的有效秒数，不是 refresh token 的寿命。长期未用、服务端撤销、refresh token 过期，或响应返回前网络中断/进程被系统杀死导致一次性令牌轮换结果丢失，都可能需要重新登录，不能保证永久登录。应用没有后台保活。

## 首页与统计

- 卡片式浅绿界面，首页优先展示今日签到；统计概览可展开查看账号余额合计、累计实际消费和今日消费，账号卡片可展开查看余额与订阅。
- **按需刷新**：首次打开、普通回到前台、跨天和修改备注不自动查询；新增/重新登录保存成功及签到页返回，只自动更新对应账号。全部刷新最多 3 个账号并发，无固定等待和分钟冷却，不自动重试。同账号正在排队/查询时合并重复点击；未启动的队列不会在进程重启后自动恢复。
- 每次账号数据查询最多 4 个 GET：`/auth/me`（身份与 `balance`）、`/usage/dashboard/stats`（`today_actual_cost` 与 `total_actual_cost`）、`/check-in`（`checked_in_today`）、`/subscriptions`（订阅明细）。有续期凭证的账号先发 1 个续期 POST，总共最多 5 次请求。登录核验和用户打开的原站网页仍会按需联网，不属于首页手动刷新限制。
- 累计使用按原站 `total_actual_cost`（实际扣除）统计，绝不改用 `total_cost`（标准计费）或余额倒推。余额来自原站 `balance`，保留负余额；金额沿用原站单位，不自行换算。余额字段与接口路径经亚洲站公开前端核对，累计字段契约参考 [Sub2API 用户统计类型](https://raw.githubusercontent.com/Wei-Shaw/sub2api/main/frontend/src/api/usage.ts)，亚洲站登录响应尚待真机核对；若字段缺失明确显示未取得。
- 汇总以本机已添加账号的最后查询快照相加，不保证同时刻。有数据立即显示合计；缺少部分账号时标注“已知”和覆盖数量，不把未知按 0 计算。
- 快照使用独立 `snapshots.enc`，复用 Keystore AES-GCM 加密，绑定来源、槽位、用户 ID 和账号修订；不保存凭证。旧 `accounts.enc` 格式不变，覆盖安装保留账号。冷启动展示上次查询时间，首次升级需手动刷新取得统计。
- 手动签到返回后不假定成功；自动刷新对应卡片核实结果，失败可手动重试。跨天只隐藏旧的今日消费/签到，余额与累计仍明确作为历史值展示。

## 使用

点击 **添加账号 → 填写备注 → 前往登录**，在 App 内原站页面正常登录并手动完成验证码。登录后自动读取该槽位的 `auth_token`，通过原站 `/auth/me` 核实身份，再返回列表并加密保存；无需查找、复制或输入 Token。登录密码只在原站页面填写，Native 不读取密码表单。

管理菜单提供 **修改备注 / 重新登录 / 删除账号及浏览器会话**。重新登录必须是原账号 ID，重复 ID 不会新增。取消或验证失败不新增/替换加密账号记录；重新登录会先清理该槽位浏览器会话，因此取消后可能需要再次登录。未保存的网页状态可能留在该槽位私有目录，下次登录会先清理；不把它当作已绑定账号。

登录复用每个账号的独立进程和 WebView 目录，主进程仅负责账号记录。仅支持原站内登录：外部 OAuth/SSO 跳转目前被阻止，第三方 Cookie 仍禁用。续期失效时选择“管理 → 重新登录”。0.3.0 的首页手动刷新会先续期再读取数据；没有后台定时续期。Token 有效期由原站决定，代码没有保证固定时长。旧版已保存的 Token/Cookie 账号记录继续兼容，但缺少 refresh token 时无法自动续期。

显示金额直接采用 `today_actual_cost`，不自行换算币种；签到采用严格布尔字段 `checked_in_today`。所有日数据请求带 `timezone=Asia/Shanghai`。

**亚洲域名切换**：API、WebView、Cookie 导入及导航校验统一使用 `Policy.ORIGIN`，仅允许 `https://asia.nexavlinks.com`，不自动回退旧域名。会话指纹包含来源域名，升级后首次打开槽位会清理旧浏览器状态并重新核验；旧凭证若无效，请更新为亚洲站登录凭证。

**线上核对与限制**：`https://asia.nexavlinks.com/doc` 返回 HTTP 200，但为客户端渲染页面，未提取到文档正文。其公开主 JS 已确认使用 `auth_token` / `auth_user` 和 `/auth/me`；页面公开配置声明 `Asia/Shanghai`。尚未登录验证消费/签到响应、`/check-in` 页面及验证码兼容性，仍需真机验收。默认禁用第三方 Cookie，外部顶层导航被阻止；若验证码依赖这些功能，应先诊断具体需求，不要直接开放所有来源。原站页面本身仍是受信任的执行内容；这不是针对恶意原站脚本的安全隔离。
